Boundary

Models from MiniModel.org and the community

MiniModel.org is preparing server-seeded models for TinyRustLM. The catalog is currently empty. Models must pass verification before they are offered; your conversations run in your browser.

  • Six exact members form one composition identity.
  • Peer bytes move directly between consenting endpoints.
  • Public peer URLs require HTTPS and HTTP is loopback-only.
  • Local conversion uses one immutable public source revision.
  • Every imported member is independently verified before activation.

One visible route

Peer first, otherwise explicit local conversion

The selected operation stays visible. A failed route does not silently choose another peer, start conversion, invoke remote inference, or download an instruction file.

  1. ResolveBind the exact catalog, source, composition, profile, qualification, and runtime identities.
  2. SelectUse one current exact peer announcement or one user-approved pinned-source conversion.
  3. TransferMove fixed verified pieces with bounded concurrency, cancellation, and durable progress.
  4. VerifyRecompute every member digest, member-set closure, evidence binding, and installation identity.
  5. ActivatePublish one immutable local activation only after the complete transaction passes.

Memory boundary

MemoryEndpoints has two separate uses

Ecosystem agents use MemoryEndpoints.com directly for long-term memory, meetings, handoffs, and coordination. Separately, a TinyRustLM.com Connect user can sign in through its plugin and select MemoryEndpoints.com as long-term memory.

  • Agent and user identities, credentials, consent, scopes, provenance, and receipts stay separate.
  • MemoryEndpoints is not a catalog, peer relay, model-byte transport, or inference service.
  • Prelaunch memory may be duplicated elsewhere only while every maintained copy stays current and noncontradictory.
