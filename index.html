MiniModel.org

A planned source catalog for checksum-bound tiny model packages that users bring locally, discover externally, transfer by consent, verify, and run locally.

View roadmap Manifest draft Catalog JSON Open SLM Composer

Boundary

MiniModel.org is not a model hosting service and not an inference service. The goal is discovery, external source routing, peer transfer, checksum verification, license routing, and local import.

  • No server-side model execution.
  • No hosted runnable model weights from MiniModel.org.
  • Every package is identified by checksums and provenance.
  • Users choose, obtain, verify, and run models locally.

Build plan

Roadmap

  1. 01

    Manifest

    Define a signed MiniModel manifest for `.slm` packages, source identity, license route, tokenizer/config checksums, eval evidence, and final artifact checksum.

  2. 02

    Verifier

    Ship a Rust CLI that verifies package bytes, manifest fields, evidence routes, drift cases, and SLMComposer import readiness before a user trusts a file.

  3. 03

    Catalog

    Publish static catalog metadata and signed index snapshots. The catalog routes users to sources and peers without serving model weights.

  4. 04

    Peer App

    Build a Rust desktop peer app for discovery, chunk transfer, resume, checksum validation, and local handoff to SLMComposer.

  5. 05

    Browser Handoff

    Let verified local `.slm` files open in SLMComposer for browser-local Rust/WASM loading and generation.

The full working roadmap is tracked in ROADMAP.md.

Source lanes

Model options

Local

User-owned `.slm` files and local JSON lists stay first-class, with browser file-picker import and Rust/WASM validation.

Hugging Face

User-triggered external discovery can route model cards, metadata, file hints, and source revisions without project-server proxying or inference.

P2P

Future peer transfer uses consent, chunk/Merkle verification, local receipts, and SLMComposer handoff after local `.slm` checks pass.
