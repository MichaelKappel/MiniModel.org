MiniModel.org

A planned source catalog for checksum-bound tiny model packages that users bring locally, discover externally, describe with share metadata, transfer by consent, verify, and run locally. TinyRustLM exposes the same choices as Local Files, Hugging Face, and P2P Exchange.

View roadmap Manifest draft Catalog JSON Open TinyRustLM

Boundary

MiniModel.org is not a model hosting service and not an inference service. The goal is discovery, external source routing, peer transfer, checksum verification, license routing, and local import.

  • No server-side model execution.
  • No hosted runnable model weights from MiniModel.org.
  • Every package is identified by checksums and provenance.
  • Users choose, obtain, verify, share metadata for, and run models locally.

Build plan

Roadmap

  1. 01

    Manifest

    Define a signed MiniModel manifest for `.slm` packages, source identity, license route, tokenizer/config checksums, eval evidence, and final artifact checksum.

  2. 02

    Verifier

    Use the first Rust CLI to verify package bytes, manifest fields, evidence routes, chunk/Merkle data, drift cases, and TinyRustLM import readiness before a user trusts a file.

  3. 03

    Catalog

    Publish static catalog metadata and signed index snapshots. The catalog routes users to sources and peers without serving model weights.

  4. 04

    Share Metadata

    Export a local `minimodel.local_slm_share_metadata.v0` bundle from verified `.slm` imports with artifact SHA256, chunk hashes, chunk-list SHA256, Merkle root, and disabled live-transfer flags.

  5. 05

    Peer App

    Use the first direct peer-piece fetch prototype for known consenting HTTP peers, then build toward a Rust peer app for discovery, resume, checksum validation, and local handoff to TinyRustLM.

  6. 06

    Browser Handoff

    Let verified local `.slm` files open in TinyRustLM for browser-local Rust/WASM loading and generation.

The full working roadmap is tracked in ROADMAP.md.

Source lanes

Model options

Local

User-owned `.slm` files and local JSON lists stay first-class, with browser file-picker import and Rust/WASM validation in TinyRustLM.

Hugging Face

User-triggered external discovery can route model cards, API metadata, file hints, source revisions, endpoint context, conversion-request JSON, and local Rust conversion-script handoffs without project-server proxying, downloads, or inference. The script can produce both a converted `.slm` and a `.minimodel-peer-offer` proof.

P2P

Today Rust can export, serve to a known direct HTTP peer, fetch, and reassemble local peer pieces from a verified `.slm`; broader peer discovery comes later, with consent and re-verification still required.

Research prompts

P2P Architecture

Compare Rust P2P approaches for a model package exchange: libp2p, Iroh, BitTorrent-style chunking, DHT discovery, static bootstrap registries, NAT traversal, and signed catalogs.

Hugging Face Source

Use Hub API metadata, OpenAPI docs, model-card discovery, endpoint awareness, and local conversion-script handoffs as an external source lane while keeping `/resolve/` downloads, tokens, and remote inference outside project servers.

Trust Model

Design checksum-bound manifests for `.slm` files with source SHA, config/tokenizer checksums, license route, eval evidence, quantization, byte count, and final artifact checksum.

Legal Boundary

Recommend UX language, model-card fields, consent flows, takedown handling, and a clear separation between catalog metadata, peer transfer, and local execution.
